# 写真上の多角形の辺を編集する

## Context

ユーザー要望は、幅・奥行き2値の編集ではなく、写真に重ねた任意多角形の辺をクリックして長さを指定する操作。確認により「始点を固定し、終点を動かして形状を変更する」方式を採用した。実測値から撮影カメラを再推定する操作とは別である。

## Decision

- 確定した輪郭の全辺（最後→最初の閉じ辺も含む）にクリック・キーボード操作可能な選択領域を設ける。頂点番号は確定後に表示しない。
- 選択した辺の近くに長さ入力を表示する。m単位で指定し、始点を固定、地面上の辺方向を維持して終点だけを移動する。入力範囲は0.1〜70m。終点を共有する隣辺の変更後の長さを適用前に示す。
- 写真上の画素距離をそのままmにしない。校正済み写真は固定した撮影カメラの逆投影とY=0との交点から実寸長を求め、移動した終点を同じカメラで写真へ再投影する。
- 未校正の旧方式も操作可能にし、土台基準の概算であると入力欄に明示する。初回の辺編集で `photo.projectionSize`（幅・奥行き）を保存し、`photo.corners` と合わせて基準変換を固定する。土台の外枠が拡張されても寸法が再び引き伸ばされないようにする。
- 写真外、自己交差、退化した輪郭、地面に逆投影できない入力は拒否する。土台の外枠は必要なときだけ中心を維持して拡張し、各軸50mを超える編集は拒否する。
- 写真と3Dは同じ輪郭・同じ変換を使用する。既存の配置物と校正パラメータは変更しない。輪郭の変更によって配置物が輪郭外へ出る場合も、自動で移動・削除しない。
- APIは輪郭の自己交差・範囲・実寸への変換を検証する。旧データのcorners内包含規則は従来形式だけに適用し、校正／固定変換がある形式では、cornersは変換用基準点、boundaryは独立した輪郭として扱う。
- 保存は既存のrevision付きスナップショットPUTとphoto_jsonを使用する。Three.jsオブジェクトは永続化しない。追加フィールドは省略可能で、DBマイグレーションは不要。

## 画面構成

写真が主作業面。辺の入力は選択位置の近くに表示し、パネル自身と写真領域の実際の寸法に合わせて画面内に配置する。リサイズや入力エラーによる高さの変化にも追従する。Esc・取消・適用後は選択していた辺へフォーカスを戻す。右パネルは配置物の選択・変形、下部トレーは素材カタログとし、個別に開閉できる。写真のない矩形の全体寸法は3D画面上部の「土台設定」からダイアログで編集する。詳細は[ワークスペースUI](workspace-ui.md)を参照。

## Alternatives

- すべての辺長を固定する制約ソルバー：多角形は辺長だけでは形が一意に定まらず、角度・対角線等の追加条件が必要。
- 輪郭を写真に固定したまま実測値で校正：今回確認された形状編集の意図とは異なる。
- 全体の一様拡縮：選択していない辺もすべて変わり、個別の辺編集にならない。

## Consequences・検証

指定辺と隣接辺の長さが連動する。写真上の元の庭に一致していた輪郭も、編集後は形が変わる。未校正画像の値は物理的な撮影精度を保証しない。

重点E2Eで6頂点の凹多角形、閉じ辺の編集、基準矩形外への拡張、自己交差・画像外入力の拒否、実API/MySQL保存復元を確認する。校正済み写真についても辺の編集後にカメラと配置物が維持され、長さが復元することを確認する。証跡は `artifacts/e2e/polygon-edges.json`、`polygon-edge-editor.png`、`camera-calibrated-edge.json`。途中の失敗traceは専用のfailureフォルダに保持する。
