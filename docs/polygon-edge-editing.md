# 写真上の輪郭を固定した辺の実寸編集

## Context

2026-10-11。辺をクリックした計測パネルから実寸を直接入力する。利用者が選択した方針は、現在のパースを保ち、指定した辺を基準として庭全体を同じ比率で変更すること。以前の読み取り専用計測を置き換える。

## Decision

- 全辺と閉じ辺をクリック・Enter・Spaceで選択する。「辺の長さ（m）」へフォーカスし、文字列を選択する。
- Enterまたは「長さを適用」で一括更新し、パネルを開いたまま更新後の値を表示する。「取消」・Esc・閉じるは未適用の入力を破棄し、辺へフォーカスを戻す。適用済みの変更は維持する。
- 倍率は入力実寸÷現在の辺長。庭の幅・奥行き、projectionSizeがある場合の幅・奥行き、配置物のX/Z座標を同じ倍率で更新する。
- calibrationがある場合はreferenceWidth/referenceDepthとtranslationの3成分を同じ倍率で更新する。rotation、focalLengthPx、focalSource、基準点は維持する。カメラの位置と地面座標が同時に変わるため、写真上の接地位置は保たれる。
- 写真、boundary、corners、配置物ID、Y=0、回転、物体倍率は変更しない。商品の実物サイズを保つため、モデルの見かけの大きさは新しい縮尺に従う。ほかの辺長は倍率倍、面積は倍率の二乗倍になる。
- 空欄、ゼロ、負数、非数値、計測不能を拒否する。庭とprojectionSizeは1〜50m、カメラ基準寸法は0.1〜50mの既存制限を適用する。拒否時は元の庭を維持して理由を表示する。
- 保存中、カメラ設定中、配置物のドラッグ中、輪郭描画中はUIとstoreの両方で適用を禁止する。
- ローカルの更新後は未保存とし、既存PUTとrevision照合で確定する。サーバーは既存処理で基準寸法からカメラを再計算する。新API・JSON項目・DBマイグレーションは追加しない。

## Alternatives

終点を移動する方式は写真との一致を壊すため採用しない。各辺の独立指定やパースの再推定も今回の対象外。辺長の上書き表示だけを保存せず、実際の庭データと計測値を一致させる。

## Consequences・確認

未校正写真は現在の近似投影を使用する。辺長入力だけで撮影カメラの角度・画角は推定しない。既存の写真カメラ設定から4基準点と長方形の実寸を指定できる。

関連テストは `npm run test:e2e -- photo-scale.spec.ts polygon-edges.spec.ts photo-calibration.spec.ts garden-dimensions.spec.ts`。実FastAPI・専用MySQLを使用し、輪郭座標、配置物の接地位置、比例変化、入力エラー、取消、連続変更、保存復元、390px表示を確認する。証跡は `artifacts/e2e/photo-scale-*.json` と `.png` に保存する。

2026-10-11確認結果：関連8件（既存5件、新規3件）が通過。lint・E2E型チェック・Webビルド成功。未校正／固定投影／校正済みで輪郭と頂点の一致、接地位置の投影差0.1px未満、寸法1.5倍・面積2.25倍、保存復元を確認。PCと390pxの画面画像を確認した。実写真の測量精度を保証する検証ではない。
