# 写真上の多角形の辺を計測する

## Context

2026-10-06。従来の辺長入力は始点を固定して終点を動かし、隣接辺も変形させていた。写真に重ねた庭の輪郭が実測値の入力で崩れるため、辺の形状編集を読み取り専用計測へ変更する。実測値によるカメラ校正は既存の4基準点と基準長方形の幅・奥行きを使用する。

## Decision

- 確定した輪郭の全辺（閉じ辺も含む）にクリック・Enter・Spaceで選択できる領域を設ける。辺の近くに「現在の実寸」または未校正時の「現在の概算」を表示する。
- 辺を選択・計測しても boundary、corners、projectionSize、calibration、土台寸法、配置物、revision、未保存状態は変更しない。入力欄、適用ボタン、終点移動処理、隣辺の変化表示を廃止する。
- 校正済み写真の長さは同じ撮影カメラの逆投影とY=0の交点から算出する。旧写真は従来のcornersとprojectionSize（なければ土台寸法）の変換を使い、概算であることを表示する。地面に逆投影できない場合は計測不能として表示する。
- 実測値は「写真のカメラを設定」で入力する。基準幅・奥行きの変更後に計算・適用し、通常は写真上の輪郭座標を維持する。基準長方形への輪郭置換は既存の明示的な選択時だけ行う。
- 頂点ドラッグと輪郭の描き直しは明示的な輪郭編集として継続する。校正・計測とは別の操作である。
- 計測表示の閉じる操作・Escで選択した辺へフォーカスを戻す。ResizeObserverで画面内の位置を調整する。
- JSON・API・photo_json列は変更せず、旧写真の保存形式と既存の固定変換を維持する。新しい辺長保存項目やDBマイグレーションは追加しない。

## Alternatives

- 終点移動：写真と輪郭の一致を壊すため廃止する。
- 任意多角形の辺長だけによる校正：形状と撮影条件が一般には一意に定まらないため、今回の校正入力には使わない。
- 辺長の目標値の別保存：計測値と入力値が二重管理になり、今回の読み取り専用表示には不要である。

## Consequences・検証

辺の実測値は基準長方形の校正画面で指定する。任意輪郭の各辺を独立入力する操作は提供しない。未校正写真の長さは概算、校正済み写真の長さも水平な地面と基準寸法の正しさを前提とする。

実FastAPI・専用MySQLを使うChromium E2Eで6頂点の凹多角形の全辺・閉じ辺、マウスとキーボード、表示の開閉、画面リサイズ、3D切替、保存データの不変と再読込みを検証する。旧写真とprojectionSizeを持つ旧固定変換の双方を対象にする。校正済み写真では基準寸法の変更・計算・適用後も輪郭が固定され、計測値が更新・保存復元されることを確認する。

証跡は artifacts/e2e/edge-measurement-legacy.json、edge-measurement-fixed-projection.json、edge-measurement-reloaded-*.png、camera-calibrated-measurement.json / .png。失敗時のtraceはPlaywrightの検証成果物に保持する。

2026-10-06の実行結果：表示ありChromiumで全21件成功。静的検査、E2E型チェック、本番ビルドも成功。詳細は `artifacts/e2e/edge-measurement-verification.json`。合成写真による検証であり、実庭写真の測量精度は未検証。
