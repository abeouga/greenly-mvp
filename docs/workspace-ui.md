# 庭エディタの画面構成

## Context

2026-10-02。従来の左右サイドバーと二段ヘッダーが作業面を圧迫し、写真・辺・カメラ・配置物の操作が離れていた。要求は、装飾を増やすことではなく、庭を編集する順序に合わせて画面とポップアップを再設計し、既存の保存・編集動作を維持すること。

## Decision

- 上部1段に、一覧へ戻る操作、庭名、寸法情報、未保存状態、保存を集約する。ロゴから戻る場合も未保存確認を通す。
- 写真／3Dの切替と、その表示に必要な操作を作業面の上に配置する。キャンバスは残りの高さと幅を使い、通常のPC画面ではページ全体をスクロールせず編集する。
- 素材カタログは下部の横並びトレーへ移す。種類と寸法を見て配置でき、同種の連続配置を維持する。Escで配置モードを解除する。
- 右の「配置と編集」は、選択した配置物の変形、配置一覧の順で表示する。カタログと独立して開閉でき、閉じた分だけ作業面を広げる。
- 多角形の長さは辺の近くの非モーダル入力で編集する。始点固定・終点移動と、隣辺への影響をその場で示す。ResizeObserverでポップアップと写真領域の大きさを測り、領域内に位置を調整する。
- 土台寸法、カメラ設定、削除確認、未保存確認には共通のDialogを使う。カメラ設定は写真と基準点を左、実測値と計算結果を右に配置し、適用／取消は下部に固定する。
- ネイティブdialogをportalで表示し、背面を操作対象から外す。Tabの移動範囲、Esc、初期フォーカス、呼び出し元への復帰を揃える。削除・未保存の確認では取消側に初期フォーカスを置く。処理中の削除／カメラ計算は閉じる操作を無効にする。
- 共通色・フォーム、作業面、写真、ダイアログ、一覧のCSSを分ける。SVGのアイコンと素材図はコード内で定義し、外部フォント・画像・UIライブラリは追加しない。

## Alternatives

- 既存3列の余白・色だけを変更する案では、作業面と操作位置の問題を解消できない。
- すべての操作を右側へまとめる案では、写真上の辺との対応が離れ、素材選択と変形が競合する。
- キャンバス全面を覆う常設フローティングパネルは、写真の頂点や配置操作を遮る。常設パネルは作業面の外に置き、辺の入力だけを局所表示にする。

## Consequences

写真・多角形・カメラ・配置物のGardenDocumentとMySQLの構造、Three.jsの座標・透視投影・配置ルールは維持する。土台設定などのモーダルを開いている間は、閉じてから保存や庭の配置に戻る。写真モードでは数値で変形するため、3D専用ハンドルの切替ボタンを表示しない。

全E2Eで、以前追加された未設定の `calibration` / `projectionSize` がnullとして出力され、旧写真のJSON比較Lが失敗する互換性問題を検出した。旧データの期待値は変更せず、Pydantic Fieldの `exclude_if` でこの2項目だけ未設定時に省略する。入力の省略／nullは引き続き受理し、設定済みの値は維持する。庭本体の `photo: null` は従来どおり出力する。DBマイグレーションは不要。

デスクトップ用画面を対象にする。カタログは狭い幅で横スクロールし、ダイアログは画面高さに合わせて内容部分がスクロールする。スマートフォン専用UIは今回の対象に含まない。

## 検証

実FastAPIと専用MySQLを使用するChromium E2Eを利用する。

- 既存A〜R：作成、配置、ドラッグ、回転、拡縮、複製、削除、通信失敗と再試行、競合、GLB再読込、写真輪郭、カメラ校正、寸法、辺編集、保存・復元。
- S：カタログと編集パネルの独立開閉、1280×800の作業面、配置終了のEsc、未適用寸法の取消、Tabの循環、Deleteの背面伝播防止、未保存確認とフォーカス復帰、削除確認の取消。
- Rに追加：1024×768で辺の入力が写真領域内に収まること、カメラ設定の取消で庭JSONが変わらないこと。

再読み込み後の画面とAPI JSONは `artifacts/e2e/workspace-reloaded.png` / `.json`、辺とカメラ設定は `workspace-edge-1024.png` / `workspace-camera-dialog.png`、削除確認は `workspace-delete-dialog.png`。途中で検出したフォーカス不具合のtraceは `workspace-first-failures/` と `workspace-focus-failure/` に保持する。

2026-10-02の最終実行：`npm run precheck`、`npm run build:web` は成功、`npm run test:e2e` は20件すべて成功（1.8分）。旧写真の互換性失敗時のtraceは `workspace-legacy-failure/` に保存した。開発用APIとWebを再起動し、8080/5173のHTTP 200とChromeでの表示も確認済み。実写真の撮影精度については、このUI検証の対象外。
