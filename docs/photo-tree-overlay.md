# 写真上への庭木表示

## Context

写真モードは地面上の丸い配置マーカーだけを表示していた。要求は、3D庭で置いた木を写真上にも実際の3D形状で表示し、写真上でも木を置けること、頂点番号を確定後に隠すこと、領域を書き直せることである。

## Decision

- 写真のSVG内に透明なR3Fキャンバスを重ねる。GardenDocument.objectsを3D庭と共有し、GardenModelで同じGLB、回転、倍率、位置を描く。写真上のモデルをクリックして選択し、既存のプロパティで編集できる。
- 写真ではOrbitControlsを使用せず、Three.jsのOrthographicCameraを土台に投影行列を固定する。保存済み地面変換に合わせ、地面Y=0の根元位置は従来の写真座標に一致させる。高さYは画像の縦座標だけに加え、横座標と透視除算の分母には加えない。画面の左右でも幹と選択枠の縦辺が垂直になる。木ごとの回転補正や別画像は生成しない。
- カメラは庭寸法と保存済みphoto.cornersから再生成する。高さの表示倍率は庭中心の幅方向の1mに対応する画素数から求める。地面の奥行き変換は保持するが、撮影位置や垂直方向の消失点は推定しない。projectionMatrixInverseも更新する。旧形式の地面変換は射影変換の場合があるため、Raycasterは同じ逆行列で深度中央付近の2点を逆投影して生成し、標準の平行投影用レイ生成には依存しない。
- 配置処理はGardenGroundを共有する。写真の表示サイズ・SVGの拡縮に合わせて、実際のキャンバス矩形からポインターを正規化し、同じ地面メッシュにレイを当てる。輪郭外、視点を動かすためのドラッグ、保存中のクリックでは配置しない。
- 頂点番号は輪郭描画中に限る。確定後は番号のない頂点ハンドルを維持し、「庭の領域を書き直す」で空の下書きを開始する。取消では旧輪郭へ戻り、始点で閉じて確定した時だけ置き換える。配置物のID・3D位置を維持する。
- モデルの読み込み失敗・再試行は3D庭と同じ処理を使う。写真の「配置」チェックでモデル描画を切り替える。保存は既存のrevision付きスナップショットPUTを使い、DB・DTO・schemaVersionを変更しない。

## Alternatives

- 丸いマーカーや木のアイコンだけでは、要求されたThree.jsモデルの重ね表示を満たさない。
- 写真用に別のモデルや別の配置リストを持つと、両画面の位置・回転・倍率と保存状態が食い違う。
- 撮影カメラの推定は、写真と任意輪郭だけでは高さ方向の実測情報が不足する。今回の固定視点は見た目を共有するための近似とする。
- 当初の有限距離のカメラ中心を仮定した拡張は、高さによって横位置も変化し、画面端の木が斜めに見えた。地面の対応だけでは根拠のない垂直方向の消失点を導入するため、垂直方向を平行にする方式へ変更した。

## Consequences

写真画面でもWebGLとGLB読み込みが必要になる。木は写真の上に3D形状として描画されるが、撮影カメラとの一致、写真内の既存物による遮蔽、現実の照明・影の再現は保証しない。頂点や輪郭を変更すると、既存オブジェクトの3D座標を保ったまま写真上の根元位置が変わる場合がある。

Three.jsのカメラ行列とレイ生成の契約は[Camera](https://threejs.org/docs/pages/Camera.html)と[Raycaster](https://threejs.org/docs/pages/Raycaster.html)を参照した。
